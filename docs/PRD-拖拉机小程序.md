## 1. 产品目标与定位

### 1.1 产品定位

- **平台**：微信小程序，即点即玩，无需下载安装。
- **形态**：单机对战 —— 1 名真人玩家 + 3 个 AI，4 人 2v2（玩家北家 AI 为队友，东/西家 AI 为对手）。
- **玩法**：传统拖拉机（双副牌 108 张、级牌从 2 开始、打对家、80 分上台）。
- **阶段策略**：先发布单机版跑通玩法正确性、AI 体验与微信审核/发布流程；联机对战列为 P2。

### 1.2 产品目标（3 个正交目标）

1. **规则正确**：完整、精确实现传统拖拉机规则，规则引擎将所有可变量参数化，用户后续提出规则调整时，仅需改配置、不改玩法框架（目标：规则调整 1 天内可上线验证版）。
2. **单局可玩性**：单局时长控制在 8~15 分钟，AI 出牌合法率 100%、有明显策略性（能配合队友、会抢分保底），让玩家"输得明白、赢得爽"。
3. **轻量易上手**：新玩家 3 分钟内开始第一局；页面极简（首页/牌桌/结算三页）；内置规则速查与出牌提示。

### 1.3 非目标（本期不做）

- 联机对战、好友房、语音聊天（P2 及以后）。
- 账号体系、排行榜（P2）。
- 皮肤/道具/付费（远期）。

## 2. 用户故事（核心场景）

1. 作为一名**资深拖拉机玩家**，我想在手机上随时来一局和真人规则一致的单机拖拉机，以便碎片时间过牌瘾。
2. 作为一名**新手玩家**，我希望系统强制只能出合法牌、并提供"能出什么"的提示，以便我在不懂全部规则的情况下也能完成对局并逐步学会规则。
3. 作为一名**新手玩家**，我想随时查看当前级数、主牌花色、双方得分和规则说明，以便随时理解局面。
4. 作为**未来的联机玩家**（P2 预留），我希望单机版的成绩和对局习惯（如常用设置）能被记录，以便后续联机版无缝衔接。
5. 作为**产品方 Kingta**，我想通过一个配置文件调整具体规则（如上台分数、抠底倍数、是否允许无主），以便验证我自己习惯的地方打法，而不需要重新开发。

## 4. 规则参数化设计（核心约定）

**所有规则可变量集中在一个 `RuleConfig` 配置对象中**，代码中不得出现硬编码规则数值。本 PRD 中每个可调规则点以【可调 ID】标注，汇总见 §7 参数总表。

```jsonc
// RuleConfig 示例（默认值 = 本 PRD 传统规则）
{
  "deckCount": 2,            // R1 副数
  "bottomCards": 8,          // R2 底牌张数
  "rankStart": 2,            // R3 起始级牌（2）
  "rankEnd": "A",            // R4 终局级牌（A）
  "pointsToTake": 80,        // R5 上台分
  "pointsPerLevel": 40,      // R6 每级分数
  "cleanSweepBonusLevels": 1,// R7 大光额外升级数
  "allowNoTrump": true,      // R8 是否允许无主局
  "bottomMultiplier": 2,     // R9 抠底分数倍数
  "bottomMultiplierByType": false, // R10 按牌型加倍（对子4x/拖拉机8x）
  "mustFollowPairAsPair": true,    // R11 有对必跟对
  "mustFollowTractorAsTractor": true, // R12 有拖必跟拖
  "offSuitRankTieFirstWin": true,  // R13 副级牌先出为大
  "throwPenalty": "smallest",      // R14 甩牌不成立的罚则
  "passACondition": "small_light", // R15 过 A 条件

  "bidDeadLine": "before_bottom_flip", // R17 亮主截止时机
  "levelUpTable": "standard"       // R18 升级幅度表
}
```

## 5. 完整游戏规则定义（默认值 = 传统规则）

> 本章精确到可直接编码的程度。所有【可调】点见 §7。

### 5.1 牌构成（R1）

- **双副牌共 108 张** = 54 × 2，**含大小王**（每副大王 1 + 小王 1，共 大王 2 张 + 小王 2 张）。
- 每副 54 = 4 花色 × 13（A K Q J 10 9 8 7 6 5 4 3 2）+ 大小王各 1。
- **分牌**：所有 5（每张 5 分）、10（每张 10 分）、K（每张 10 分）。总分 = 8×5 + 8×10 + 8×10 = **200 分**。
- 同名同花色牌视为相同牌（如两张♠10 等价），存在"对子"概念：两张同名同花色牌天然成对。

### 5.2 人数、阵营、座位（R0）

- 4 人，两两组队 **2v2**；**对面（北）为队友**，左右为对手。
- 座位固定：玩家 = 南；AI 依次 西、北（队友）、东。
- 出牌顺序：**逆时针**（南→东→北→西→南，即逆时针轮转）【可调 R19：顺时针】。

### 5.3 级牌与主牌

- 每队各有自己的**级数**（当前打几），初始均为 2（R3）。当某队为庄时，**以庄家队的级数 X 为本局级牌**（本局"打 X"）。
- **级牌**：4 种花色的 X，共 8 张（双副）。级牌永远属于主牌，无论花色。
- **主牌构成（有主局，主花色为 S）**：
  1. 大王 ×2
  2. 小王 ×2
  3. 主花色级牌 S-X ×2
  4. 副花色级牌（其他三门 X）×6 —— 副级牌之间不比大小，先出为大【可调 R13】
  5. 主花色其余牌 S-A, S-K, …, S-3（跳过 X 本身）共 24 张
  - 合计 36 张主牌；三门副牌各 24 张，共 72 张。
- **主牌大小顺序**：大王 > 小王 > S-X > 副X（先出为大）> S-A > S-K > … > S-3。
- **无主局（若 R8 开启）**：主牌仅 = 大王、小王、8 张级牌（共 12 张）；四门花色均为副牌；级牌之间先出为大。
- **副牌大小顺序**（每门内）：A > K > Q > J > 10 > 9 > 8 > 7 > 6 > 5 > 4 > 3 > 2（级牌 X 不在该门内，因其属主牌）。

### 5.4 发牌

- 洗牌后按逆时针逐张（或每轮 1 张）发牌，每人 **25 张**，余 **8 张为底牌**（R2：25×4+8=108）。
- 发牌过程即进入**亮主阶段**（见 5.5），发牌结束仍无人亮主时：**翻开底牌第一张**，其花色即为主花色（若为王，继续翻下一张）【可调 R20：底牌定主规则，可改为"首局随机重发"】。

### 5.5 亮主 / 叫主 / 反主（R8、R17）

- **亮主窗口**：从发出第一张牌起，到**底牌翻开前**的任意时刻（R17）。
- **亮主（叫主）**：手中有级牌 X 的玩家可将 **一张** 级牌亮出，其花色成为主花色，亮主者暂定为庄家（首局）。
- **反主（改主）**：亮主可被"反"，优先级从高到低：
  1. **对王反主（无主）**：任意**一对大王**或**一对小王** → 反成**无主局**（需 R8 开启；关闭则王不可反主）。
  2. **对级牌反主**：**两张同花色级牌**（如两张♥X）→ 主花色改为该花色。
  - 单张王不可反主【可调 R21：允许单王反无主】；反主后原亮主者不可再反回；同一优先级只能出现一次（对王 > 对级牌，后者不可反前者）。
- 亮/反主均需**亮出牌面**公开展示，亮出的牌收回手牌（不影响手牌）。
- **首局庄家**：最终定主者坐庄。无人亮主时翻底定主，庄家随机（R16/R20）。

### 5.6 换底（埋底）

- 庄家收起 8 张底牌（加入手牌，此时手牌 33 张），再**任选 8 张扣下作为新底牌**（面向下，他人不可见；分牌可埋底"藏分"）。
- 底牌在整局中不参与出牌，仅在最后一墩结算时按"抠底"规则处理（5.10）。
- 埋底完成后庄家领出第一墩。

### 5.7 牌型定义

- **单张**：任意 1 张。
- **对子**：同名同花色 2 张（主牌对子 = 两张相同主牌，如两张大王、两张 S-X、两张 S-A；注意两张**不同花色**的副级牌**不是**对子）。
- **拖拉机**：**同一花色**内、按该花色大小序**相邻**的对子序列，至少 2 对。
  - 副牌拖拉机：如 ♠55+♠66、♠KK+♠AA、♠33+♠44。
  - 主牌拖拉机（按主牌序相邻）：如 对大王+对小王、对小王+对S-X、对S-X+对副X（需两张**同花色**副X）、对副X+对S-A、S-AA+S-KK 等。
  - **例外**：两张不同花色的副级牌对（如 ♠X对 + ♣X对）大小相同、不相邻，**不构成**拖拉机【可调 R22】。
  - 拖拉机可 >2 对（如 55+66+77 三对拖）。比较时长度相同才直接比大小；长度不同按跟牌规则处理（见 5.9）。
- **甩牌**：同花色（或全主牌）的**多单元组合**，各单元（单张/对子/拖拉机）之间**不构成**一个完整拖拉机结构（如 A+K+55 三张；或 KK+7+8）。甩牌张数 = 各单元张数之和。

### 5.8 甩牌成立条件与罚则（R14）

- 领出甩牌时必须满足：**其他三家没有同花色（或主牌域）、同结构且严格更大的单元**。同样大的牌不能压住先出的牌。
  - 判定时必须考虑对手对子和拖拉机中可以拆出的单张/对子，不能只检查已拆出的同张数单元而忽略更大组合。
  - 三打一默认 `sanDaYiAllowTractor=false`：连对也作为多副对子逐对检查；如 99+1010 遇到对手 QQ，应甩牌失败。只有各个对子都无人能压时，才可一起甩出。传统升级模式保留拖拉机。
  - 简化判定（推荐默认实现）：**单张单元**要求该单张为手中+场上该门已知最大；**对子单元**要求其他三家无人持有更大的该门对子。逐一校验，全部通过才允许甩。
- **甩牌不成立的罚则**（R14）：`smallest` 只出**本次甩牌中被压住的最小单元**，其余收回。优先最小单张，无失败单张时出最小失败对子（保持对子完整）；不得抽取未选的小牌，也不维持原甩牌张数。`penalty_smallest` 在此基础上按原甩牌张数每张罚 10 分给对方；`reject` 直接禁止甩出。

### 5.9 出牌与跟牌规则（R11、R12）

- **领出**（每墩第一家）：可出任意合法牌型：单张 / 对子 / 拖拉机（≥2 对）/ 甩牌（须满足 5.8）。领出张数 n 即本墩每人出牌张数。
- **跟牌**（按逆时针依次）：
  1. **有领出花色（副牌）**：必须跟出该花色牌 n 张；结构优先级（严格模式，R11/R12 默认开）：
     - 领出**拖拉机**（k 对连）：优先跟同花色 k 对拖拉机 → 无则同花色对子（不足部分用单张补齐）→ 无对则单张垫足 n 张。允许拆更长拖拉机跟 k 对【可调】。
     - 领出**对子**：有对必须跟对（不可拆）→ 无对则 2 张单张。
     - 领出**单张**：跟任意 1 张该花色。
     - 领出**甩牌**：跟出该花色任意 n 张（结构自由），但只有组成"每单元压过领出对应单元"的结构才可能赢墩（见 5.11）。
  2. **领出是主牌**：上述规则同，"该花色"= 主牌域。
  3. **无该花色（缺门）**：可二选一：
     - **垫牌**：任意其他副牌 n 张（不参与争胜）；
     - **将吃**：出主牌 n 张。**将吃必须结构对应才有效争胜**：领出对子须用主对；领出 k 对拖须用主牌 k 对拖；领出甩牌须用主牌同结构全压；领出单张出任意主单。结构不对应的主牌（如用 2 张主单应对对子）视为垫牌，不争胜。
- 玩家手牌不足 n 张的极端情况不存在（25 张能整除所有领出张数组合不会越界，规则引擎仍需防御：剩余不足时全出）。

### 5.10 墩（trick）胜负判定与抠底（R9、R10）

- **胜负判定**（按争胜资格依次比较）：
  1. 有效将吃的主牌 > 一切副牌；多主牌之间按主牌序比。
  2. 同为领出花色副牌：按领出结构逐单元比较：拖拉机 > （更长的对子序列不参与，长度须一致）；同结构比最大单元：拖头（最大一对）大者胜；对子比对；甩牌需**每个单元**都压过领出/此前跟牌的对应单元才算争胜成功。
  3. 多家依次压过时，**后压过者胜**（同一墩内逐家结算，最终最大者赢墩）。
  4. 垫牌永远不争胜。
- **赢墩者**：收走本墩 4 家所出牌中的分牌（计入己方——注意：庄家方与攻方的分都归"赢墩方"所属阵营），并**领出下一墩**。
- **抠底**：**最后一墩**的赢家获得底牌 8 张中所有分牌，按 R9 加倍计入该阵营得分：
  - 默认：底牌分 ×2（R9=2）。
  - 可选（R10）：按最后一墩赢牌牌型加倍 —— 单张 ×2 / 对子 ×4 / 拖拉机 ×6（或 ×8），甩牌取最大单元牌型倍数。
  - 若最后一墩由庄家方赢，底牌分不产生额外得分（庄家方本来就无须抓分），仅收回。

### 5.11 一局计分与胜负（R5、R6）

- 攻方（非庄家方）累计全局抓分 S（含抠底加倍）。
- 庄家方目标：把攻方得分压在 80 分（R5）以下。

### 5.12 升级规则（R18 默认 `standard`，40 分一级）

- 升级幅度默认表（S = 攻方得分，每 40 分一级，R6）：

| 攻方得分 S     | 结果         | 升级数                |
| ---------- | ---------- | ------------------ |
| 0（大光）      | 庄家方升       | **3 级**（2+大光奖1，R7） |
| 1 ~ 39（小光） | 庄家方升       | **2 级**            |
| 40 ~ 79    | 庄家方升       | **1 级**            |
| 80 ~ 119   | **攻方上台**，升 | **1 级**            |
| 120 ~ 159  | 攻方上台，升     | 2 级                |
| 160 ~ 199  | 攻方上台，升     | 3 级                |
| 200（全场）    | 攻方上台，升     | 4 级                |

- 公式化：攻方胜时升级数 = 1 + floor((S−80)/40)（200 封顶 4）；庄家方胜时 = 2 − floor(S/40)（0 分再 +1）。
- **升级**：获胜方级数 += 升级数，跳过无意义序号（级牌序固定 2→3→…→K→A，无跳序）。
- **上台/下台**：攻方 S ≥ 80 → 攻方下局当庄（"上台"）；否则庄家方继续当庄。

### 5.13 庄家传递（R16）

- 默认 `winner_stays`：庄家方胜 → **原庄家连庄**；攻方上台 → 攻方当庄，**具体成员 = 本局亮主/反主最终定主的攻方成员**；若本局是翻底定主（无人亮主），由攻方中**上局庄家的下家**当庄。
- 备选：`rotate`（获胜方两人轮换坐庄）、`bidder_always`（每局都抢庄，抢到者坐庄，不限阵营）【见 Q6】。

### 5.14 过 A 与终局（R15）

- 某队级数升到 A 后须"过 A"才算通过：
  - 默认 `small_light`（严过）：该队当庄打 A 时，需让对方得分 **< 40 分**（小光）方可过 A；否则停在 A（按小光正常升 2 级但级数封顶 A，下局继续打 A）。
  - 备选：`win`（赢局即过）、`big_light`（0 分过）。
- **过 A 后**：该队完成一整轮（2→A）。默认玩法目标：**先过 A 的队伍获胜**，弹出结算（胜利画面）；可选循环模式（过 A 后回到 2 继续，P1 增加"长局模式"）。

### 5.15 王与特殊牌处理

- 大小王永远为主牌；对大王、对小王各为对子；大王对+小王对构成**王拖拉机**（最大拖拉机）。
- 打 A 时主花色序为：大王>小王>S-A>副A>S-K>…>S-3。

## 8. AI 对手需求

### 8.1 P0 基础版（必须）

1. **合法性 100%**：AI 所有决策（亮主/反主/埋底/跟牌/甩牌）必须通过规则引擎校验，禁止任何非法出牌。
2. **亮主策略**：手中对级牌或双王 → 亮/反；仅一张级牌时首局倾向早亮抢庄，非首局按庄家传递规则决定是否抢。
3. **埋底策略**：主牌强（≥10 张主或有大拖）时分牌可埋底藏分；主牌弱则埋废牌保手上灵活。
4. **出牌策略（贪心启发式）**：
   - 庄家/主多时优先出主拖/大对清主；
   - 末家（本墩最后出牌）且必赢时出分牌收分；
   - 能赢且有分时用"最小的能赢牌"；赢不了时垫最小牌或垫分给已稳赢的队友；
   - 缺门时墩内有 ≥10 分则将吃，否则垫；
   - 末墩抠底意识：能赢末墩且攻方时优先最大牌抠底。
5. **甩牌**：仅在确定成立（基于自己的牌与已出牌）时甩，否则出安全牌型。

### 8.2 P1 进阶版

- 记牌（跟踪已出的级牌/王/分牌）、队友信号配合（队友甩牌跟分）、难度分级（简单=纯贪心+随机、普通=基础、困难=全记牌+概率估算）。

## 10. 验收标准（P0）

1. 按默认 RuleConfig 完成 2→A 完整一轮对局无规则错误（QA 用例覆盖：亮/反主、无主、甩牌、将吃结构对应、抠底、大光、过A）。
2. 修改任一 RuleConfig 参数（如 R5=60）后重开局，规则即时生效且规则速查页文案同步变化。
3. AI 全程零非法出牌（QA 压测 ≥100 局）。
4. 单局时长（4 人出牌节奏默认）在 8~15 分钟区间。
5. 小程序切后台 5 分钟内返回可恢复当前对局。
