## 1. 规则事实卡（写策略前必读，防止想当然）

以引擎代码为准核对过，**与升级模式的最大差异**加粗：

| 规则 | 事实 | 出处 |
| ---- | ---- | ---- |
| 牌与手牌 | 双副 108 张，各 25 张 + 底 8 张 | `rule-config.js` |
| 主牌 | 恒打 2：王(4) + 全部 2(8) + 主花色(24) = **36 张，占全牌 1/3** | `engine/trump.js` |
| 选主 | 庄家**不受手牌限制**，自由选主花色 | `decideTrumpSuit` |
| 报分 | 90 起步长 10 封顶 160，报满即成交；全员不叫重发 | `engine/config.js` R26 |
| 牌型 | **无拖拉机**（默认 `sanDaYiAllowTractor:false`）：连对=多副对子甩牌，逐对检查成立性；牌型只有单/对/甩 | `engine/combo.js` |
| 分牌 | 5/10/K，全场共 200 分 | `pointValues` |
| 甩牌失败 | 每张罚 10 分**加给对方阵营**（甩三张=白送 30 分，可改写胜负） | `engine/settle.js` L166 |
| **末墩抠底** | **底分 ×1 不翻倍**，末墩赢家整包拿走；无牌型加倍（R9/R10 倍数仅存在于升级模式）。末墩=「墩内分+底分（埋底均值~35）」的普通大墩 | `engine/settle.js` L171-176 |
| 胜负 | 庄分 ≥ 合同 → 庄胜；**无升级表/过A**，阶跃式胜负，连局记战绩 | `engine/settle.js` L184-204 |
| 埋底实测 | 副牌分 1v3 护不住，庄家「全埋副牌分」最优：庄分 +8.4、达标率 +14.8pp | `decideBury` 注释 |

**经济结构推论**：合同 90~160 = 庄家需拿 45%~80% 的分；胜负是阶跃的 → **卡点分（庄家差几分时每一墩的边际价值）远大于连续计分制**；末墩无放大器 → 储备/守底按平移价值（`BOTTOM_POINTS_EXP=35`）标定即正确。

## 2. 验证流程（铁律：不过基准不算改进）

1. `node tools/ai-bench.js 400`（同种子 A/B，判定：**d-new 庄胜率 > base 且 a-new < base**，双向都强才算）
2. `node tests/run-tests.js`（230 用例全过，含 AI 合法性、分守恒 200）
3. **逐项消融归因**：多个启发式改动必须分别用临时开关（env/副本文件）跑 bench 定位贡献，禁止一把梭混合验证
4. 教训存档：2026-10-24「庄家示缺门就避让该门」直觉合理但实测让攻方大幅变弱（58.8%），**反转成主动领空牌逼烧主后 43.0%**——三打一三家主牌总量碾压一家，逼庄烧主是核心配合手段。方向必须靠基准定，不靠直觉。
5. 教训存档：2026-10-24「庄家差≤20 分该兑现顶主抢成庄墩」直觉合理但实测 **−4.3pp**——庄家提前烧顶主，攻方全垫空牌，末段控制与底分双失。**囤顶主罚是庄家生命线**；同样负的还有 urgency 银行分（−0.3pp）与「庄家示缺门禁甩牌」（攻方 −0.8pp，误伤正期望逼烧主甩牌）。

## 3. 路线图（优先级序，完成打勾并记入 §4 台账）

### 第一梯队：打分函数内改动（不动架构，随时可做）

- [x] **R1 合同意识**（2026-10-24，部分落地）：`need` 接入出牌打分。✅ **R1A 攻方卡点否决**：庄家 need≤墩内潜在分时夺墩=直接否决合同，豁免末墩储备/主牌经济罚、垫分重罚（a-new 43.0%→42.8%）。✅ **R1D 庄家成庄墩**：赢墩即跨线的墩 +10 并优先稳赢/最大牌（实测中性，保留——原则正确零成本）。❌ 两个反直觉负结果存档：庄家差≤20 分解除囤顶主罚（nearLine 兑现）d-new **−4.3pp**——提前烧顶主后攻方全垫空牌，控制与底分双失，囤主罚不能动；need/未见分 urgency 银行分 **−0.3pp** 已删。庄家侧合同意识的启发式空间已试尽，再往上靠 R3 推演。
- [x] **R2 甩牌风险管理**（2026-10-24，重新定性）：**关键引擎事实——AI 甩牌永不罚分**（`legalMoves`→`validatePlay`→`validateThrow` 用真实手牌校验，罚分只发生在真人甩错）。真实风险=缺门家结构将吃整墩夺走：实测攻方副牌甩牌 36% 被庄家将吃夺墩（18/50 全是缺门将吃，送庄 100 分），但总暴露仅 ~0.25 分/局、期望仍为正（65% 成功银行分+逼烧主）。落地：隐性缺门按该门未见牌密度罚带分甩牌（实测贡献≈0，保留作廉价保险）；❌ 重罚版（庄家示缺门禁甩）a-new **−0.8pp** 已回退——把正期望的逼烧主甩牌一起禁掉了。
- [x] **R0a 顶主守底**（2026-10-24）：庄家非末墩不领「剩余牌无敌」顶主，持单大王首墩领出 100%→0%。
- [x] **R0b 锁墩喂分**（2026-10-24）：庄家夺不走的墩，攻方全力喂分、绝不超压队友；副牌赢牌不作锁墩依据（防未示出缺门将吃偷分）。
- [x] **R0c 逼烧主配合领出**（2026-10-24）：往庄家示缺门领空牌（带分仍罚）。

### 第二梯队：从「打分」升「推演」（架构升级，单项收益最大）

- [x] **R3 PIMC 蒙特卡洛推演**（2026-10-24，v1）：手牌 3~10 的关键跟牌（墩分 ≥10 或卡点墩=墩分 ≥need，庄家赢即达标/攻方夺走即否决）→ 按记牌器固定种子采样三家手牌分布（**共同随机数**：同组分布评所有候选，差分方差远小于独立采样；按已示缺门过滤）→ 模拟态上全员基线贪心快走打到收局 → 比期望 V=庄家终局分−合同分。**只当最优候选比贪心选择高出 τ=10 分才覆盖**：消融 τ∈{0,3,5,8,10,12}，τ=0 全覆盖双向微降（d −0.3/a +0.2）——10~24 采样的 EV 噪声会推翻大量基准校准过的先验（尤其庄家囤主，弱 rollout 低估留主价值）；τ=10 只留高置信覆盖，1600 局仅 45 次但全在卡点墩。实测 d-new 55.8→56.0、a-new 41.3→40.3（增益几乎全在攻方侧，`AI_R3_CAMP` 消融归因；单决策均 ~10ms/峰 26ms，bench 已加耗时列监控真机预算）。**基建事故存档**：`_r5Assignments` 全枚举在 R3 尺寸池（35 张）+ 缺门剪枝下，深层组几乎填不满 → 结果数长期不涨、永不触发 240 上限 → 组合树裸搜**单次 222 秒**（bench 400 局 20 分钟才定位到）；修复=枚举加 30 万节点预算护栏 + R3 大池跳过枚举直接采样。
- [x] **R4 对手手牌推断**（2026-10-24，v1）：探针实测合同分档无区分度（90 分占 89%），真正的机制是**庄家自选主花色 → 持主天然富集**：400 局实测（h=5/8/12 稳定）合同 90 庄家占未见主牌 ~57%、合同 100 ~75%，而均匀采样只给 ~25%。落地：R3 采样分布按「庄家持主数 = 份额×未见主牌数」重要性重采样（采 3× 排序取前 N；份额 0.57 + 每分合同 +2pp 封顶 0.8），攻方视角生效。实测 a-new 40.3→40.0。❌ 两个未落地/负结果存档：「能压未压」大牌下修未做——需精确建模对手出牌策略（本 AI 有意弃赢的场景多：末墩储备/卡点否决豁免/锁墩喂分），误建模注入噪声；R5 采样接同一先验实测 40.0→40.3 **反而变差**（h=2 池仅 14 张、未见主 1~2 张，加权失真），已回退并留注释。缺门信号 R3 采样本就按 `_r5SeatVoids` 过滤。
- [x] **R5 残局精确求解**（2026-10-24，v1）：手牌恰 2 张的决策位（跟牌留哪张 / 领出拆单 vs 整对——手牌=本墩张数时出牌唯一无选择权，自动跳过）→ 枚举/采样未见牌分布（庄家 90 种全枚举并剔除真底牌；攻方固定种子采样 48 种、余牌即假设底牌，按已示缺门过滤）→ 每候选完全信息 minimax（fail-soft α-β，庄家最大化/攻方最小化 V=庄家终局分−合同分）打到全场手牌空。**实测 d-new 54.3%→55.8%、a-new 42.8%→41.3%（双向 +1.5pp）**；求解 ~1 次/局、均 4.7ms / 峰 22ms；节点超限整体回退贪心，bench 复跑逐位一致。已知妥协：PIMC 对手知情过强（末两墩影响有限）；胜负已定（need≤0 或 need>未见分）不求解。v2 方向：h=3 树太深，等 R3 基建（rollout 评估替代全展开）。

### 第三梯队：配合深化与赛前阶段

- [x] **R6 攻方信号/分工**（2026-10-24，v1=让路落地，只基于公开信息，合规）：✅ **R6B 高主让路**：庄家未出、队友在压王/2 级主（强度 ≥950，主花色 A 顶格 914 不算）→ 超压 −12——能反压的只剩更大的王（大概率不在庄家手里），超压=再烧一张顶级主抢已近乎到手的墩（攻分是团队总分）。实测 **0 触发/100 局**（需我持王/2 且队友也在压王/2，极稀有牌型）、基准零影响——纯灾难性烧牌保险，保留（原则正确、成本可忽略）。❌ **R6A 续攻队友空门**（队友示缺该门且庄家未示缺→领小单喂将吃）负结果存档：直觉上近乎白赚一墩，实测占攻方领出 8.8% 但 a-new 40.0→41.0（**−1.0pp**），权重扫描 +6/+3/+2 = 41.0/41.0/40.8 单调有害——机制：①花**队友**的主牌将吃近乎空墩（坏主牌经济，与逼烧主的「烧庄家的主」方向相反）；②+6 会诱使我方大单（如 A）领进队友缺门被自己人将吃废掉。方向本身负，非权重问题，已回退；「连续垫某门→续攻」同机制预期同负，未做。顺带落地：缺门情报改单次按席位扫描派生庄家/攻方视图（免二次扫描，基准逐位一致）。
- [x] **R7 选主+埋底+竞价联合优化**（2026-10-24，v1=选主落地）：离线打表（200 种子×4 花色强制自对弈）实测启发式选主仅 **51% 命中最优花色、平均每局差 16.7 分**、46/200 局差 30+，且 argmax 仅 78.5% 在启发式 top-2（砍候选会恰好丢掉启发式错得最狠的案例）。落地：CHOOSE_TRUMP 态（庄家已并底 33 张，底牌已知）固定种子采 5 组三家手牌（共同随机数），4 花色各逐组基线贪心快打到 SCORING，取庄分均值 argmax、启发式分千分位 tie-break；预算消融 M=3 **52.8% 反而低于纯启发式**（采样噪声翻错花色）、M=5 甜点、M=8 无增益。实测 d-new 56.0→56.5、all-new 54.0→55.8（a-new 不动）；每局 +63ms 一次性成本（藏在发牌动画内）。**未做（理由）**：埋底——打表内所有花色共用现有「全埋副牌分」规则（此前已实测 +8.4 分碾压备选），per-suit 埋底候选 × 花色成本翻倍收益存疑；竞价——bench 把 decideScoreBid 固定路由 baseline（保证同合同可比），竞价改进**无法在现基准验证**，等 R8 Elo 天梯解锁后再动。
- [x] **R8 基准升级为 Elo 天梯**（2026-10-25，`tools/ai-elo.js`）：多版本同池循环赛 + 在线 Elo（K=8）。**竞价解锁**：四家真实竞价（各家自己的 decideScoreBid，含开叫/抬价/pass），X 未抢到庄的局弃用不计——R7 遗留的竞价改动从此可验证（聚焦实验 `node tools/ai-elo.js 800 base full` ~3 分钟）。版本=新策略+完整特性开关组合（cache-busting 重加载同进程多实例，隔离性已验证：载序无关、不同开关结果不同）；版本链 base/v4/+R1/+R2/+R5/+R3/+R4/+R7/full 即分阶段消融，可用版本名参数取子集。机制校准：座位效应大（固定 0 号位当庄 −6pp）→ 庄位随种子轮转；真实竞价保留率 ~24%，种子预算≠计入局数；绝对庄胜率与 ai-bench 不可直接比（竞价选择效应），看排名与差分。**验证**（budget=800，n≈193/格）：base 自对 52.3%↔bench 51.2%、base 当庄 vs full 攻方 41.2%↔a-new 40.0%、full 当庄 vs base 攻方 53.4%↔d-new 56.5%（1σ 内）——双向梯度复现。教训存档：❌首版「攻方强制 pass」方案——X 永远首叫 90，抬价逻辑走不到，恰好废掉竞价验证主用途，已改真实竞价；链上近邻版本（R1/R2/R4/R5 各 ≤1.5pp）在 n≲50/格时排序全在噪声里（全链 200 预算跑出家族内 Elo 乱序），且对称提升在 new 家族互打时互相抵消（矩阵核心全在 48% 平价带）——天梯只对 vs-base 大梯度、R7/竞价类每局触发改动、以及聚焦高 n 对比有效，显著性仍以 ai-bench 400 为准。

### 建议实施顺序

R1 → R2 → R5 → R3 → R4 → R7 → R6 → R8。R1/R2 直接可验证；R3 是分水岭（贪心→推演），其后 R4/R5/R6 都在给它喂更好的输入。

## 5. 已知弱点清单（改 AI 时的自查起点）
