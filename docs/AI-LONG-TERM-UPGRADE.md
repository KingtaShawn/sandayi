## 1. 规则事实卡（写策略前必读，防止想当然）

以引擎代码为准核对过，**与升级模式的最大差异**加粗：

| 规则 | 事实 | 出处 |
| ---- | ---- | ---- |
| 牌与手牌 | 双副 108 张，各 25 张 + 底 8 张 | `rule-config.js` |
| 主牌 | 恒打 2：王(4) + 全部 2(8) + 主花色(24) = **36 张，占全牌 1/3** | `engine/trump.js` |
| 选主 | 庄家**不受手牌限制**，自由选主花色 | `decideTrumpSuit` |
| 报分 | 90 起步长 10 封顶 160，报满即成交；全员不叫重发 | `engine/config.js` R26 |
| 牌型 | **无拖拉机**（默认 `sanDaYiAllowTractor:false`）：连对=多副对子甩牌，逐对检查成立性；牌型只有单/对/甩 | `engine/combo.js` |
| 分牌 | 5/10/K，全场共 200 分 | `pointValues` |
| 甩牌失败 | 每张罚 10 分**加给对方阵营**（甩三张=白送 30 分，可改写胜负） | `engine/settle.js` L166 |
| **末墩抠底** | **底分 ×1 不翻倍**，末墩赢家整包拿走；无牌型加倍（R9/R10 倍数仅存在于升级模式）。末墩=「墩内分+底分（埋底均值~35）」的普通大墩 | `engine/settle.js` L171-176 |
| 胜负 | 庄分 ≥ 合同 → 庄胜；**无升级表/过A**，阶跃式胜负，连局记战绩 | `engine/settle.js` L184-204 |
| 埋底实测 | 副牌分 1v3 护不住，庄家「全埋副牌分」最优：庄分 +8.4、达标率 +14.8pp | `decideBury` 注释 |

**经济结构推论**：合同 90~160 = 庄家需拿 45%~80% 的分；胜负是阶跃的 → **卡点分（庄家差几分时每一墩的边际价值）远大于连续计分制**；末墩无放大器 → 储备/守底按平移价值（`BOTTOM_POINTS_EXP=35`）标定即正确。

## 2. 验证流程（铁律：不过基准不算改进）

1. `node tools/ai-bench.js 400`（同种子 A/B，判定：**d-new 庄胜率 > base 且 a-new < base**，双向都强才算）
2. `node tests/run-tests.js`（230 用例全过，含 AI 合法性、分守恒 200）
3. **逐项消融归因**：多个启发式改动必须分别用临时开关（env/副本文件）跑 bench 定位贡献，禁止一把梭混合验证
4. 教训存档：2026-10-24「庄家示缺门就避让该门」直觉合理但实测让攻方大幅变弱（58.8%），**反转成主动领空牌逼烧主后 43.0%**——三打一三家主牌总量碾压一家，逼庄烧主是核心配合手段。方向必须靠基准定，不靠直觉。
5. 教训存档：2026-10-24「庄家差≤20 分该兑现顶主抢成庄墩」直觉合理但实测 **−4.3pp**——庄家提前烧顶主，攻方全垫空牌，末段控制与底分双失。**囤顶主罚是庄家生命线**；同样负的还有 urgency 银行分（−0.3pp）与「庄家示缺门禁甩牌」（攻方 −0.8pp，误伤正期望逼烧主甩牌）。
6. 教训存档：2026-10-28「攻方让牌原则」（非末家+队友在压+庄家未出 → 白墩/小分墩垫小不超压队友、大分墩最小能赢接手）**全负回退**：只副牌域让牌 a-new 39.8（噪声带内）、只垫牌分域归一 41.5（−1.5pp）、全开 42.8（−2.8pp）。三个机制结论：① **副牌墩「队友在压」≠稳赢**——庄家缺门将吃/更大同门牌风险永存（lock 不认副牌赢牌同理），让牌=送庄家压走队友裸奔的墩；② **主牌墩「压队友大牌」实为攻方主牌接力**（甲小王→乙大王→庄家无解），是三家主牌总量优势的兑现方式，让牌=放庄家小主白捡墩+领出权——v4 的「能赢就赢」本身就是强行为；③ 攻方隐式协调类配合（让牌/省牌/续攻空门）已试尽全负（R6A、本轮），**配合的上限=公开信息**（锁墩喂分/缺门逼烧主/卡点否决/末墩储备，均已落地），下一突破只可能在推演（R3 rollout 换增强策略）而非新启发式。
7. 教训存档（打分函数基建）：**strength 数值域两极**——副牌 3~14、主牌 903~1000 差两个数量级。任何线性用 strength 的项在主牌域要么无区分度（/100 → 9~10）、要么吞掉基础分（/50 → 18~20，曾令接手分支 14−s/50 永不生效）；旧垫牌项 (20−s)/20·6 对主牌产生 −265~−294 失真负值，令一切「罚 X 分让 AI 放弃赢墩」的设计失效（超压罚 6/12、清主经济罚 16 全穿不透——**这个失真其实是 v4「能赢就赢」的隐形实现机制，修复它=激活省牌让墩=实测负**）。另：**领出者不在 trick.plays 里**，`dealerPlayed=false` 不代表庄家未表态（庄家可能是领出者）——判定「队友在压」必须用 `teamWinning`（当前赢墩者阵营），不能只看 dealerPlayed。
8. 教训存档：2026-10-28「攻方保对子/养缺门甩牌结构」直觉合理但**三形态全负**（普遍保对 −2pp、大户养结构 −1.5pp、空甩加成无效）。机制：攻方保结构是**先付机会成本（垫牌扭曲）、后等不确定兑现**——而 1v3 清场威胁下兑现时刻近乎不存在（探针 100 局仅 5 次缺门甩牌被选）；对子牌型价值在**庄家侧**才成立（清场甩牌收割），攻方侧「缺门逐张小单逼烧主」严格优于整甩（一张一墩烧庄家主、保留对子后手控制）。同一资产反向用法的对照（v6.3）：主牌战已输时**垫牌保**副牌无敌大牌=正（a-new −1.0pp），**领出**同批大牌=负（+1.8pp）——保着等庄家领非最大牌时反压是被动兑现（零风险），领出去闯庄家隐性缺门是主动送检（自带分+丢逼烧主节奏）。另：bench 的 base 行是 R1~R8 之前的旧快照，**消融对照锚点=特性全关行**，勿拿 base 当「改动前」。
9. 教训存档：2026-10-28 R12 送分风险两条：① **同族启发式各自有效≠叠加有效**——喂分折减与超压罚同源于「庄家未出+暗处更大牌别送分」，单开各 −0.5pp、合体 +0.8pp（攻方在未锁墩上全面不敢接盘，接盘通道只剩一条时才是最优）；② **风险折减要设门槛，无门槛全折连正期望试探一起砍**——J 在压时喂 10 期望 +2.4（约 6 成站住），真正负 EV 是 3 家 K 超压把试探堆成整墩赌注；≥4 张暗处更大才起折（地板 0.1）比任意更大即折好 1.0pp。「送分」拆开看：试探喂分是攻方得分主通道，被支配超压才是白送。

## 3. 路线图（优先级序，完成打勾并记入 §4 台账）

### 第一梯队：打分函数内改动（不动架构，随时可做）

- [x] **R1 合同意识**（2026-10-24，部分落地）：`need` 接入出牌打分。✅ **R1A 攻方卡点否决**：庄家 need≤墩内潜在分时夺墩=直接否决合同，豁免末墩储备/主牌经济罚、垫分重罚（a-new 43.0%→42.8%）。✅ **R1D 庄家成庄墩**：赢墩即跨线的墩 +10 并优先稳赢/最大牌（实测中性，保留——原则正确零成本）。❌ 两个反直觉负结果存档：庄家差≤20 分解除囤顶主罚（nearLine 兑现）d-new **−4.3pp**——提前烧顶主后攻方全垫空牌，控制与底分双失，囤主罚不能动；need/未见分 urgency 银行分 **−0.3pp** 已删。庄家侧合同意识的启发式空间已试尽，再往上靠 R3 推演。
- [x] **R2 甩牌风险管理**（2026-10-24，重新定性）：**关键引擎事实——AI 甩牌永不罚分**（`legalMoves`→`validatePlay`→`validateThrow` 用真实手牌校验，罚分只发生在真人甩错）。真实风险=缺门家结构将吃整墩夺走：实测攻方副牌甩牌 36% 被庄家将吃夺墩（18/50 全是缺门将吃，送庄 100 分），但总暴露仅 ~0.25 分/局、期望仍为正（65% 成功银行分+逼烧主）。落地：隐性缺门按该门未见牌密度罚带分甩牌（实测贡献≈0，保留作廉价保险）；❌ 重罚版（庄家示缺门禁甩）a-new **−0.8pp** 已回退——把正期望的逼烧主甩牌一起禁掉了。
- [x] **R0a 顶主守底**（2026-10-24）：庄家非末墩不领「剩余牌无敌」顶主，持单大王首墩领出 100%→0%。
- [x] **R0b 锁墩喂分**（2026-10-24）：庄家夺不走的墩，攻方全力喂分、绝不超压队友；副牌赢牌不作锁墩依据（防未示出缺门将吃偷分）。
- [x] **R0c 逼烧主配合领出**（2026-10-24）：往庄家示缺门领空牌（带分仍罚）。
- [x] **R0d 结构防守**（2026-10-28）：✅ **庄家侧拆对保护**（AI_PAIR）：垫牌拆对罚 4 + JQKA 大单保护 1.2、领出小单拆对罚 3——庄家清场甩牌收割靠对子结构，拆小对应劣于垫大单（d-new 56.5→58.8，a-new 不动=纯庄家侧）。✅ **满分防守**（AI_SWEEP，v6.3 触发重设计）：触发不在 ≥180 分（那时已无力回天），而在**主牌战已输**的局势事实——我无主 + 两队友已示主牌缺门（新增 `_trumpVoidSeats`：主牌墩一张主没跟=缺门，独立于 `_r5SeatVoids` 不进 R3/R5 采样）+ 未见主牌 >0 → 剩余主牌权全归庄家、满分在望，此刻即防守。落地两件：① 抢分豁免/垫分加倍（>=180 终局模式保留，实测近乎零翻转）；② **垫牌保副牌「剩余牌无敌」大牌罚 8**（庄家已示缺门死牌除外）——主牌战已输后这是唯一能走墩抢分的资产（庄家领非最大牌时反压赢墩、队友喂分入袋；seed 374 墩16 把 D/C 两门 A 当垃圾垫掉即典型失误）。实测 a-new 40.0→**39.0**（守榜同时直接否决合同，庄家均分 84.6→84.0）。❌ **「大牌走墩」领出加成负结果存档**（同触发下 +8 副牌无敌领出）：a-new 40.0→41.8——大牌对子自带 10~20 分进隐性缺门将吃白送庄家，且挤掉实证 +8.8pp 的逼烧主节奏；大牌的正确用法是留着反压庄家控牌领出，不是领出去送检。❌ **攻方缺门养甩全负存档**：普遍保对 −2pp（1v3 清场威胁下攻方对子结构难兑现，保对的机会成本=垫牌扭曲立即支付）；大户（缺门 ≥3 张）养对/大单 −1.5pp；配套「缺门空甩张数加成」无效果（探针 100 局：76 次手握缺门甩牌候选仅 5 次选甩、≥3 张 2 次）——**逐张小单逼烧主在牌效上严格优于整甩**（一次只暴露一张、保留对子后续控制、弹药消耗更细），「等一家养好结构一次甩出」在三打一 1v3 形态下不成立。
- [x] **R12 送分风险（喂分折减）**（2026-10-28，AI_FEEDRISK，用户局例驱动——「方块全未出，下家领 J，两攻方垫 10/超 K，庄家 A 白吃 20 分」）：攻方未锁墩喂分打分 `pts*1.5` 原为无风险全额——落地风险折减：**仅压「队友在压牌真的很弱」的极端情形**（`_unseenHigher` 暗处更大 ≥4 张，如全门未出 J 在压时 Q/K/A×2=6 张暗牌，喂 10 ≈ 白送）+ **庄家已示缺门的副牌墩=将吃口**分牌折到两成（R0c 逼烧主的墩只送空牌）；≤3 张视为正常试探全额喂。❌ **配套超压罚负结果存档**（非无敌副牌不超压队友：K 压队友 J 而 A 在暗处——单开 37.0 有效、探针风险超压 89→42/百局减半，但与喂分折减叠加攻方未锁墩全面不敢接盘：严苛合体 38.3、软化合体 37.0 均劣于单开 36.0，已回退）；❌ **无门槛全折版否掉**（任意暗处更大即折 hi*0.3：单开 37.0、合体 38.3——把正期望的中等风险试探喂分也砍了；J 在压时 2 家喂 10 期望实为 +2.4，真正负 EV 是 3 家 K 超压把试探堆成赌注）。

### 第二梯队：从「打分」升「推演」（架构升级，单项收益最大）

- [x] **R3 PIMC 蒙特卡洛推演**（2026-10-24，v1）：手牌 3~10 的关键跟牌（墩分 ≥10 或卡点墩=墩分 ≥need，庄家赢即达标/攻方夺走即否决）→ 按记牌器固定种子采样三家手牌分布（**共同随机数**：同组分布评所有候选，差分方差远小于独立采样；按已示缺门过滤）→ 模拟态上全员基线贪心快走打到收局 → 比期望 V=庄家终局分−合同分。**只当最优候选比贪心选择高出 τ=10 分才覆盖**：消融 τ∈{0,3,5,8,10,12}，τ=0 全覆盖双向微降（d −0.3/a +0.2）——10~24 采样的 EV 噪声会推翻大量基准校准过的先验（尤其庄家囤主，弱 rollout 低估留主价值）；τ=10 只留高置信覆盖，1600 局仅 45 次但全在卡点墩。实测 d-new 55.8→56.0、a-new 41.3→40.3（增益几乎全在攻方侧，`AI_R3_CAMP` 消融归因；单决策均 ~10ms/峰 26ms，bench 已加耗时列监控真机预算）。**基建事故存档**：`_r5Assignments` 全枚举在 R3 尺寸池（35 张）+ 缺门剪枝下，深层组几乎填不满 → 结果数长期不涨、永不触发 240 上限 → 组合树裸搜**单次 222 秒**（bench 400 局 20 分钟才定位到）；修复=枚举加 30 万节点预算护栏 + R3 大池跳过枚举直接采样。

- 埋底仍是规则式（R7 选主 rollout 内沿用该规则评估各花色，未做 per-suit 埋底候选——成本翻倍收益存疑）；竞价估价 r≈0.49，R8 天梯已解锁验证通道，两者待动。
- `legalMoves` 返回「代表性」候选集合，甩牌枚举可能漏好选项（R2 已确认 AI 甩牌永不罚分、缺门将吃是唯一败法；枚举覆盖度待 R3 做候选评估时一并检查）。
- 攻方三家无显式分工（谁清主、谁喂分、谁抠底），全靠隐式协调——R6 v1（让路/续攻）、2026-10-28 让牌原则、缺门养甩（FEED）均已实测负回退：**隐式协调类配合（让牌/省牌/续攻/养结构）已试尽全负，配合上限=公开信息（锁墩喂分/缺门逼烧主/卡点否决/末墩储备/主牌战已输后垫牌保大牌/未锁墩喂分风险折减）且已挖尽**；观感上「压队友大牌」的主牌接力实为正着（副牌侧非无敌超压单开有效但与喂分折减互斥，见 R12）。下一突破只可能在 R3 rollout 换增强策略（消除系统性低估留牌价值）或竞价改进，不在新启发式。
- `_r5SeatVoids` 存在误判：跟牌非「整墩全是领出门」即标缺门——庄家跟攻方副牌甩牌（垫牌非全同门）会被误标缺门而实际仍持有该门。影响面：R3/R4/R5 采样过滤与一切 voids 驱动的战术（逼烧主/锁墩）在「庄家跟过甩牌」后的一小段时间内用假缺门。2026-10-28 发现（v6.0 FEED 意外让庄家受益即源于此），修法=改为「完全无该门牌才标缺门」（部分跟=仅记录门内余量），待做。

## 6. 2026-10-28 攻方接力与甩牌候选实验

用户要求按出牌顺序判断自己跑分或压庄给后位队友跑分，并持续考虑甩牌消耗庄家。现有 PIMC 会采样三家手牌并依出牌顺序模拟到收局，但根候选按即时吃分排序，可能提前剔除低分甩牌或小牌接力。

本轮独立消融 `AI_RELAY`（关键跟牌时后位仍有队友，保留最少分/最小牌候选）、`AI_THROW_CHOICE`（领出时保留低分优先、同分张数多优先的合法副牌甩牌候选）。保持根候选宽度和总步数预算，仍以终局庄家得分比较选择，不因能甩就强制甩。推演范围保持手牌 3~10 张；更早阶段仍用记牌启发式，不能声称全局每手均完成了深度推演。

已否掉：把桌上不足 10 分、后位有队友且自己有分牌可出的跟牌也全部纳入推演。400 局同种子，接力单开/与甩牌合开均使 a-new 36.0→38.0，耗时约翻倍；低分局面全量扩展未通过当前基准，不能据此断言接力原则无效。

最终关键墩方案：双关对照 d-new/all-new/a-new=59.0/54.5/36.0；只保甩牌候选=59.0/54.8/36.0；只保关键墩接力候选=59.0/54.5/35.8；双开=59.0/54.8/35.8（a-new 仅多赢一局，不声称统计显著提升）。243 用例全过；浏览器全局环境载入 H5 bundle 后，10 个种子的完整对局与源码终分一致、零非法。该验证覆盖网页逻辑包，未进行真实手机视觉验证。

## 7. 2026-10-29 前期也判断接力与分牌暴露

用户明确要求不能仅剩3~10张时配合，尤其庄家未出时不能随意送10/K。新增前期单墩评估，适用于手牌11~25张、有选择权的非末家单张/对子跟牌；已锁进攻方的墩沿用喂分，强制跟牌不得绕过。3~10张保留原R3整局推演，2张保留R5残局求解。此实现补上前期跟牌，不声称所有复杂甩牌跟牌都完成同样的概率推演。

- 对同一组24个假设比较原选择、低分小垫、所有合法压牌及跑分选择，只走完本墩。按实际出牌方向估计我方胜率、后位队友接手率及本墩团队得分。样本频率依赖假设分配及基线跟牌策略，不是已知队友手牌或保证能接住。
- 庄家未出且当前准备暴露至少10分时，仅在当前队友牌弱（未见更大至少4张）或已知庄家缺门的情况下允许改选；不把预计赢墩机会减少超过25个百分点，风险调整后需至少4分优势。庄家已出时，所有有效样本均由队友接手且团队胜率不低于原选择，才以至少2分优势改为跑分。顶主/副牌控制消耗另计成本，避免只为当前墩烧掉控制牌。
- 使用自己手牌与公开出牌重建未见牌，不读取真实庄家/队友手牌和底牌。当前墩与历史半跟说明该门当时已出尽；历史散跟对子还要排除当时暗藏可跟对子的分配。倒序补回该家后续公开出的牌，由引擎validateFollow检查，至多超采4倍，有效分配不足时回退。
- 独立复查发现的反向出牌漏庄家、对子不可能分配、中间主牌候选遗漏均已修正并加回归；同一出牌方向修正亦应用于R3/R5模拟，模拟态保留playOrder。

核心场景回归：25张时J在压不主动跟10；J后已有10不再追加K；庄家已出且队友锁墩继续喂10；只有10可跟时合法跟10；后位有足够接牌能力时跑10而不多花K；够用的主Q优于大王；两种方向均不漏玩家、不改真实状态；真实隐藏手牌/底牌改为抛错getter也不影响接力估计。

验证与局限：255用例通过；H5 bundle在无process的浏览器全局环境中，双方向合计10种子完整对局与源码终分相同、零非法。400局同种子，AI_TEAM_FOLLOW=0为59.0/54.8/35.8，新策略为59.0/50.5/36.8（d-new/all-new/a-new）；增强庄家对三家新攻方时平均庄分92.2→89.4，旧庄家对新攻方平均庄分81.3→80.3。对旧庄家的合同胜率回退1个百分点，不能将得分改善等同于所有对手胜率改善；此项优先解决用户指定的前期配合场景，尚需更广对手分布验证。原型全面重排与接管残局未采纳，避免把单墩估值误当整局最优；修复复查问题后重新跑基准，上述为最终配置结果。
