## 1. 规则事实卡（写策略前必读，防止想当然）

以引擎代码为准核对过，**与升级模式的最大差异**加粗：

| 规则 | 事实 | 出处 |
| ---- | ---- | ---- |
| 牌与手牌 | 双副 108 张，各 25 张 + 底 8 张 | `rule-config.js` |
| 主牌 | 恒打 2：王(4) + 全部 2(8) + 主花色(24) = **36 张，占全牌 1/3** | `engine/trump.js` |
| 选主 | 庄家**不受手牌限制**，自由选主花色 | `decideTrumpSuit` |
| 报分 | 90 起步长 10 封顶 160，报满即成交；全员不叫重发 | `engine/config.js` R26 |
| 牌型 | **无拖拉机**（默认 `sanDaYiAllowTractor:false`）：连对=多副对子甩牌，逐对检查成立性；牌型只有单/对/甩 | `engine/combo.js` |
| 分牌 | 5/10/K，全场共 200 分 | `pointValues` |
| 甩牌失败 | 每张罚 10 分**加给对方阵营**（甩三张=白送 30 分，可改写胜负） | `engine/settle.js` L166 |
| **末墩抠底** | **底分 ×1 不翻倍**，末墩赢家整包拿走；无牌型加倍（R9/R10 倍数仅存在于升级模式）。末墩=「墩内分+底分（埋底均值~35）」的普通大墩 | `engine/settle.js` L171-176 |
| 胜负 | 庄分 ≥ 合同 → 庄胜；**无升级表/过A**，阶跃式胜负，连局记战绩 | `engine/settle.js` L184-204 |
| 埋底实测 | 副牌分 1v3 护不住，庄家「全埋副牌分」最优：庄分 +8.4、达标率 +14.8pp | `decideBury` 注释 |

**经济结构推论**：合同 90~160 = 庄家需拿 45%~80% 的分；胜负是阶跃的 → **卡点分（庄家差几分时每一墩的边际价值）远大于连续计分制**；末墩无放大器 → 储备/守底按平移价值（`BOTTOM_POINTS_EXP=35`）标定即正确。

## 2. 验证流程（铁律：不过基准不算改进）

1. `node tools/ai-bench.js 400`（同种子 A/B，判定：**d-new 庄胜率 > base 且 a-new < base**，双向都强才算）
2. `node tests/run-tests.js`（219 用例全过，含 AI 合法性、分守恒 200）
3. **逐项消融归因**：多个启发式改动必须分别用临时开关（env/副本文件）跑 bench 定位贡献，禁止一把梭混合验证
4. 教训存档：2026-10-24「庄家示缺门就避让该门」直觉合理但实测让攻方大幅变弱（58.8%），**反转成主动领空牌逼烧主后 43.0%**——三打一三家主牌总量碾压一家，逼庄烧主是核心配合手段。方向必须靠基准定，不靠直觉。

## 3. 路线图（优先级序，完成打勾并记入 §4 台账）

### 第一梯队：打分函数内改动（不动架构，随时可做）

- [ ] **R1 合同意识**：`_sdyCtx.need` 已算出但出牌打分几乎没用。庄家按 need 切方差（落后→烧主抢分；过线→低方差保底）；攻方卡点防守（庄家差 5 分时 5 分墩=15 分墩的防守价值）。阶跃胜负制下卡点价值极高。
- [ ] **R2 甩牌风险管理**：甩失败每张白送 10 分。现在「甩成立概率」无显式建模——应按记牌器未见牌估算每对被压概率，期望罚分超阈值就不甩/改甩小组合。三打一特有的大分险点。
- [x] **R0a 顶主守底**（2026-10-24）：庄家非末墩不领「剩余牌无敌」顶主，持单大王首墩领出 100%→0%。
- [x] **R0b 锁墩喂分**（2026-10-24）：庄家夺不走的墩，攻方全力喂分、绝不超压队友；副牌赢牌不作锁墩依据（防未示出缺门将吃偷分）。
- [x] **R0c 逼烧主配合领出**（2026-10-24）：往庄家示缺门领空牌（带分仍罚）。

### 第二梯队：从「打分」升「推演」（架构升级，单项收益最大）

- [ ] **R3 PIMC 蒙特卡洛推演**：枚举候选 → 按记牌器随机补全三家手牌 → rollout 打完剩余墩（用现有贪心 AI 快走）→ 比期望团队得分，采样 20~50 次取均值。建议只对关键决策启用（庄家有分墩/攻方大分墩/残局），**bench 加决策耗时列监控真机预算**（小程序/H5 单线程）。
- [ ] **R4 对手手牌推断**：未见牌按情报加权分配——缺门信号（`_voidSuitsOf` 已有）、庄家报分高低（主牌概率上修）、跟牌时「能压未压」（大牌概率下修）。给 R3 的发牌器喂更准的分布。
- [ ] **R5 残局精确求解**：剩 ≤2 墩、未见牌 ≤10 张时全枚举分布+minimax，分支极小。价值集中在底分归属与合同卡点——均分合同档位下这几墩常是胜负本身。

### 第三梯队：配合深化与赛前阶段

- [ ] **R6 攻方信号/分工**（只基于公开信息，合规）：将吃过高主→标记主强，队友清主让路；连续垫某门→队友续攻该门。把人类牌手默契规则化。
- [ ] **R7 选主+埋底+竞价联合优化**：三打一最大自由度（选主定 36 张主牌结构、埋底定 35 分存放、竞价定胜负线），现三步各自为政。方案：离线批量自对弈打表，或在线 top-K 小样本 rollout。
- [ ] **R8 基准升级为 Elo 天梯**：多版本策略同池循环赛积分 + 分阶段消融（已有 `-lead`/`-follow` 模式）；解开「竞价固定走 baseline」路由，否则 R7 竞价部分无法验证。

### 建议实施顺序

R1 → R2 → R5 → R3 → R4 → R7 → R6 → R8。R1/R2 直接可验证；R3 是分水岭（贪心→推演），其后 R4/R5/R6 都在给它喂更好的输入。

## 5. 已知弱点清单（改 AI 时的自查起点）

- 庄家/攻方领出仍是贪心基线骨架，看不见两步之后的墩权流转（等 R3/R5）。
- `estimateSanDaYiPoints` 竞价估价是手工回归（r≈0.49），对手叫/不叫信息未纳入（等 R7）。
- 埋底是规则式，未与选主联合评估（等 R7）。
- `legalMoves` 返回「代表性」候选集合，甩牌枚举可能漏好选项（做 R2 时一并检查）。
- 攻方三家无显式分工（谁清主、谁喂分、谁抠底），全靠隐式协调（等 R6）。
