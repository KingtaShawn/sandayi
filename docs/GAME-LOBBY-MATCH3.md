# 双游戏大厅与果园消消乐

## 目标与入口

首页改为游戏大厅，展示「三打一」和「果园消消乐」两张入口卡片。三打一进入原有开始、规则、账号及排行榜页面；消消乐直接进入上次进度。H5 和微信小程序共用消消乐规则、关卡及存档逻辑。

H5 大厅、消消乐按设备自然方向布局，手机优先竖屏；三打一保留原有横屏牌桌。牌桌增加返回大厅按钮，切出时暂停 AI，切回继续当前对局。

## 第一版规则

- 8×8 棋盘、6 种水果；点击两枚上下或左右相邻水果交换，H5 也支持滑动交换。
- 横向或纵向连续至少 3 枚相同水果消除；交叉位置只计一次；四连、五连均按实际消除数量计分。
- 无法产生消除的交换退回，不扣步数。有效交换扣 1 步，随后的所有连锁不额外扣步数。
- 每枚水果基础 10 分；同一次交换的第 n 次连锁使用 min(n, 5) 倍分数。
- 消除后逐列下落，顶部补齐，持续结算连锁。初始盘面没有自动消除且至少存在一步有效交换；无路可走时自动洗牌，不扣步数、不加分。
- 12 关，目标分数逐渐提高、步数逐渐收紧。达到目标即胜；最后一步先完整结算，再判胜负。通关可下一关或重玩；失败可重试。
- 提示标出一组可消除的相邻水果，不扣步数。重玩本关需要确认。
- 每步完成立即保存稳定盘面、步数、分数、关卡、最高解锁关和各关最佳分数。返回、刷新后可继续。存储不可用时仍可玩。

本版不加入特殊炸弹、障碍、体力、付费道具或云排行榜。消消乐进度只保存在当前设备，与三打一账号及成绩独立。

## 实现分层

- `miniprogram/match3/engine.js`：纯规则，注入随机源，返回逐次消除动画帧和最终稳定状态。
- `miniprogram/match3/session.js`：通过现有 storage adapter 保存独立的 `match3:progress:v1` 存档并校验恢复内容。
- H5：`arcade.css` / `match3.js`，使用现有 bundle 导出共享逻辑；动画期间锁定交换，离开页面取消动画，但保留已经结算并保存的结果。
- 小程序：新增大厅和消消乐页面，保留原有三打一首页。
- 构建给新增资源注入版本号；部署校验覆盖新增 JS/CSS。

## 验收

1. 纯规则：三连/长连/交叉、邻接边界、无效交换、重力、连锁计分、最后一步胜负、死盘恢复、初盘可玩、坏存档隔离。
2. 完整闯关模拟，检查每一步的棋盘、步数和计分不变量。
3. H5 桌面/手机竖横屏：双入口、完整消除与结算、提示、重玩、刷新继续、游戏切换及三打一暂停恢复。
4. 现有全量回归、H5 构建、`git diff --check`；提交推送后核对实际部署结果。

## 边界处理

洗牌优先保留水果数量；多次随机尝试仍失败时重新生成可玩棋盘。随机源异常造成超过 40 层连锁时重建稳定棋盘，防止无限结算。用户无需为自动恢复付出步数。小程序真机体验需在微信开发者工具/设备上补充验证。
